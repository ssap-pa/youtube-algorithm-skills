## A. 연구 갱신 (약 40분, 서브 에이전트 병렬)
1. `python <P>/scripts/yt_home_loggedout.py <T>/home<YYYYMMDD> --scrolls 30 --min-views 1000000`
   - 쿠키·이력 없는 새 크롬을 띄워 시크릿과 같은 조건을 만든다. 처음 홈은 비어 있고 Shorts를 거쳐야 채워진다. 크롬이 필요하다.
2. `python <P>/scripts/yt_longform_study.py <같은 폴더>` — 31일 이내·100만+·3분 이상, 음악·재생목록·라이브 다시보기 제외 → `candidates.tsv`, `pack/<id>.md`(메타·설명·챕터·상위 댓글·자막).
3. 포맷별 4~5갈래 서브 에이전트를 **한 메시지에 동시에** 띄운다(토크·게스트 / 지식·시사 / 브이로그·체험 / 과정·요약 / 방송 클립·스포츠 등). 브리프는 `<P>/reference/ANALYSIS-BRIEF.md`를 복사해 `<S>`·`<CH>`만 바꾼다. 조회/구독 3배 이상 영상은 "왜 퍼졌나를 문장 단위로" 따로 지시.
4. 종합: `<W>/research/LONGFORM-PLANNING-<날짜>.md`(방법·숫자·3배 이상 표·공통 패턴·따라 하면 안 되는 것 + 기준 문서와 **달라진 점**). 자막·댓글 원문과 영상별 묶음은 `<T>`에만 둔다.
5. 한계는 그대로 적는다: 다시보기 히트맵은 로그아웃으로 못 받음, 자막 없는 영상, 표본 읽기 구간, 하루치 홈 1회 표본.

## B. 진행 중 영상 점검
입력: 영상 폴더(사용자가 알려 준 곳, 없으면 `<W>/videos/<슬러그>/`). 산출: 같은 폴더의 `ALGO-CHECK.md`, `PLAN.md`.
**기존 파일(시놉시스·대본·제목안 등)은 고치지 않는다** — 제안만 쓰고, 반영은 사용자 확인 뒤에 한다. 사용자가 쓴 문구는 되돌리지 않는다.

0. 읽기: 폴더의 기획·시놉시스·대본·오프닝·제목/썸네일 안. 지금 단계(주제/시놉시스/대본/편집/오프닝/업로드)를 확인한다.
1. **소재 점검** — 모두 아는 것 × 빈칸 × 때(화제 며칠째). 기획 장치(시의성·빈칸·대비/지위 역전·인물 결합·금지/비밀·극한/규모·검증·약속 회수) 중 무엇을 쓰는지.
2. **로그라인 한 줄 + 단일 질문 + 숨길 답 + 공유될 한 줄**을 뽑아 본다. 한 줄로 안 나오면 그 자체가 1순위 지적.
3. **뼈대 판정**: A 콜드 오픈 플래시백 / B 흥망 곡선 / C 실측 판정 뒤집기 / D 과정 완성 / E 해설 요약 중 무엇에 가까운지, **답 공개 위치**(절반·2/3·끝)가 정해졌는지, 편집 단위 경계가 전환점과 맞는지.
4. **패키징**: 제목(사람·원인·질문·검색어 꼬리표) / 썸네일(결과 장면·얼굴·실제 한마디)이 역할을 나누는지. 제목 후보마다 PLANNING-WORKFLOW 3절 문형 번호를 붙이고 CHANNEL.md 제목 규칙을 적용한다.
5. **오프닝 0~60초 체크**(대본이 있으면 문장 단위, 없으면 방향): 인사 없이 첫 문장 = 가장 센 사실 · 20초마다 새 사실 · 30초 안 제목 단어 회수 · 약속 한 번 · 질문으로 본론 진입.
6. **리듬**: 예상 길이 ÷ 전환 수(10~20분 내레이션이면 1~2분마다 전환) · 재후킹 문장 위치 3곳 이상 · 반복 소품 · 약속 심기 → 회수.
7. **결말**: 단일 질문의 답 → 수미상관/판정 한 줄로 끝나는지. 엔딩 요청(좋아요·구독)은 CHANNEL.md 규칙을 따르고, 규칙이 없으면 "39개 중 37개가 구독 요청 없이 끝났다"는 데이터만 제시한다.
8. **충돌 확인**: 하지 않은 말을 인용처럼 쓰지 않았나, 숫자 단위·기간 표기, 생성 이미지 과장, 협찬이면 광고주 브리프 금지어.

## 하지 않는 것
- 사용자 파일(대본·제목안 등)을 직접 고쳐 쓰기 — 제안만.
- 패턴을 근거로 CHANNEL.md 규칙이나 사용자 결정을 뒤집기 — 데이터로만 제시.
- 터진 영상의 지어낸 인용·숫자 단위 변형·과장 생성 썸네일 따라 하기.
